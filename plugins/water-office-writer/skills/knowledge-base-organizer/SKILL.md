# 文档知识库归档整理器

把一堆散乱的多格式文档，治理成「结构清晰 + 元数据齐全 + 可批量导入知识库」的规范文档库。

## 核心原则（先想清楚，再动手）

这四条是整个方法论的骨架，任何归类决策都回到它们：

| 轴 | 管什么 | 表现形态 |
|----|--------|----------|
| **目录轴** | 「**主体 × 文档类型**」 | 决定权限边界与风格样本的同源性 |
| **标签轴** | 「**主题 / 年度 / 受众**」 | 主题（如鸿蒙、AI、国际化）一律用标签，**不建目录** |
| **密级隔离** | 公开 / 内部 / 敏感 | 公开致辞与敏感汇报**不得混装同一目录**，否则权限无法设置 |
| **零风险** | 副本先行 | 在 `_reorg_YYYYMMDD/` 副本中操作，原文件不动，用户确认后再替换 |

**关键判断规则**——有人提议"把某文件移到某目录"时，逐项比对**类型 / 受众 / 密级**三个属性：三项一致才算同源，放进同一目录；只要有一项冲突，就说明放错格子了。

**反模式**：为某个主题单独建目录（如 `03-鸿蒙专题/`）。当该目录只有 1 份文件且作者唯一时，"跨类别专题"的前提不成立，等于凭空加一层。正确做法是撤销该目录、文件归入其类型目录、主题用标签表达。目录管属性，标签管内容。

## 工作流

### 第 0 步 · 盘点

```bash
cd "<知识库根目录>"
find . -type f -not -name '~$*' | sort                    # 全量清单
find . -type f | awk -F. '{print $NF}' | sort | uniq -c   # 格式分布
find . -type f -not -name '~$*' -printf '%s %p\n' | sort -rn | head -10   # 大文件
find . -name '~$*'                                        # Office 锁文件
```

产出：文件总数 / 格式分布 / 体积分布 / 特殊文件（锁文件、旧版 .doc、超大文件）。

### 第 1 步 · 设计分类骨架

按「主体 × 文档类型」定主空间与子目录，例如：

```
知识库/
├── 00-规范制度/                  ← 制度规范独立空间，权限最高
├── 01-<主体A>（职务）/
│   ├── 集团年度工作总结/
│   ├── 集团半年工作总结/
│   └── ...
├── 02-<主体B>（职务）/
│   ├── 集团年度工作总结/
│   ├── 重要会议致辞/            ← 同一类型、同一受众、同一密级的样本聚合
│   ├── 对外汇报（部委）/        ← 敏感，独立目录便于设权限
│   ├── 专题汇报/
│   └── 就职演讲/
```

**编号规则**（两条都要遵守）：

1. **主空间按组织层级排序**：职级高者在前——董事长 `01`、总裁 `02`，制度规范固定 `00`。目录编号就是知识库里的显示顺序，"谁在上层"应当由编号直接体现。
2. **子目录按业务阅读顺序**：不要用字母序（否则"专题汇报"会排在"集团年度工作总结"前面）。推荐 `集团年度工作总结 → 集团半年工作总结 → 重要会议致辞 → 对外汇报（部委）→ 专题汇报 → 就职演讲`，并在脚本里用 `SPACE_ORDER` / `SUB_ORDER` 常量固化，让目录结构、README 索引、元数据 CSV 三者顺序完全一致。

### 第 2 步 · 生成规范文件名

```
YYYYMMDD_文档类型_清理后标题_主体.扩展名
```

**必须清理的命名噪音**：`【】` `（）` `终稿` `定稿` `第N次审稿后` 之类版本词、`0711 1300` 之类时间戳、`(1)(2)` 重复编号、`附件1`。

**必须保留**：日期、文档类型、标题、主体。同名文件用**语义后缀**区分（如 `-水利部` / `-生态环境部`），不要用 `_v2`。

### 第 3 步 · 用脚本一次性产出三件套

使用 `scripts/reorganize_template.py`（按项目改 `SRC`/`OUT`/`ITEMS`）：

```bash
PYTHONIOENCODING=utf-8 python _build/reorganize.py              # 全量重建（先清理旧输出）
PYTHONIOENCODING=utf-8 python _build/reorganize.py --no-clean   # 原地刷新（幂等复用，只重写索引与元数据）
```

调整结构（如目录编号互换、文件移位）用**全量重建**；只改元数据/标签/README 用 `--no-clean`，避免重复复制数百 MB 的大文件。脚本会按 `SPACE_ORDER` / `SUB_ORDER` 排序输出，元数据与目录顺序天然一致。

一个 `ITEMS` 数组作为**单一数据源**，同步产出：
1. 副本目录结构 + 重命名后的文件
2. `_metadata.csv`（UTF-8-BOM，供知识库批量导入）
3. `_metadata.xlsx`（冻结表头 + 自动筛选，供人工核对）
4. 各级 `README.md` 索引（主空间级 + 子目录级）

### 第 4 步 · 校验

```bash
find . -type f -not -path './_build/*' | sort   # 逐份核对
```

对照清单逐项确认：份数一致、路径正确、无 `03-` 之类已撤销目录残留、元数据行数 = 文件数、标签无遗漏。

### 第 5 步 · 用户确认后替换

副本 → 原件是**破坏性动作**，必须先让用户看过副本、明确确认，并保留脚本以便回溯。

## 元数据字段（知识库导入的通用形态）

| 字段 | 说明 |
|------|------|
| `src_rel` | 原始相对路径（可追溯） |
| `src_size_mb` | 原文件体积 |
| `new_path` | 新路径（含主空间/子目录） |
| `new_filename` | 新文件名 |
| `type` | 文档类型（年终总结/半年总结/致辞/讲话/对外汇报/专题汇报/就职演讲/规范） |
| `date` | 日期 YYYY-MM-DD |
| `title_clean` | 清理后标题 |
| `leader` | 主体/领导 |
| `audience` | 受众（全员/行业协会/部委/市政府/公众） |
| `security` | 密级（公开/内部/敏感/机密） |
| `tags` | 标签（含主题，如 `鸿蒙`、`AI`、`智慧水务`） |
| `notes` | 处理提示（旧版格式、大文件等） |

## 已知坑与对策（实操血泪）

| 坑 | 现象 | 对策 |
|----|------|------|
| **中文路径下 `find -exec` 失效** | `find: The environment is too large for exec()` | 不用 `-exec`，直接 `rm -rf '目录名1' '目录名2'` 逐项列出 |
| **GBK 编码崩输出** | 打印中文报 `UnicodeEncodeError` | 运行前设 `PYTHONIOENCODING=utf-8`；脚本内避免 `✓/✗` 等符号，改用 `[OK]/[FAIL]` |
| **重跑前清理误删脚本** | 清空输出目录时把 `_build/reorganize.py` 一起删了 | 清空时**排除 `_build`**；或先把脚本复制到输出目录之外 |
| **重复执行产生 `_v2` 副本** | 中断后重跑，同名文件被改名叠加 | 脚本内置**幂等复用**：目标已存在且大小与源一致 → 直接复用 |
| **大文件被进程占用删不掉** | `Device or resource busy`（常见于 400MB+ 的 pptx） | 幂等复用绕过；锁文件用脚本末尾的 `~$*` 自动清理逻辑处理，失败则静默跳过 |
| **Office 锁文件混入交付** | 目录里出现 `~$xxx.pptx` | 盘点阶段排除；生成阶段主动清理；它不影响上传（可忽略） |
| **两级 README 逻辑错乱** | 生成出 `(根)/README.md` 这类异常 | 主空间 README 与子目录 README 分开处理；无二级目录的空间把清单直接写进主空间 README |
| **输出目录无法删除/重命名** | 残留目录清不掉，报 `WinError 32`（另一个程序正在使用）或 `Permission denied`；`~$` 锁文件被同步/索引/杀毒客户端独占 | 不要硬删。用 `--no-clean` 原地刷新绕开；无法清理的残留目录放入 `_待清理说明.md`（写明来历 + 删除方法），避免日后被误当作有效数据 |

## 验收清单

- [ ] 文件总数 = 原始有效文件数（无遗漏、无重复）
- [ ] 目录层级 ≤ 3 层，主空间用 `00/01/02` 前缀，且**编号顺序符合组织层级**（职级高者在前）
- [ ] 子目录、README 索引、元数据 CSV 三者的顺序一致（按业务顺序，非字母序）
- [ ] 所有文件符合 `YYYYMMDD_类型_标题_主体.ext` 命名
- [ ] 公开类与敏感类**不在同一目录**
- [ ] 主题类聚合需求通过**标签**满足，未新建主题目录
- [ ] `_metadata.csv` 行数 = 文件数，字段完整
- [ ] 每个目录都有 `README.md`，清单与实际文件一致
- [ ] 原文件 100% 保留，副本可回溯，脚本可重跑

## 后续动作（用户确认后可选）

- **上传知识库**：用 `_metadata.csv` 逐行创建空间/目录，上传文件，写入标签与权限
- **格式预处理**：旧版 `.doc` → `.docx`；超大 PPT 压缩或转 PDF（>100MB 易上传超时）
- **增量维护**：新文件只需往 `ITEMS` 追加一条再重跑（幂等，不会重复复制）
